# 2026-11-13 版实施盘点

规范来自 2026-11-13 的审查后方案。SHA-256 为 `7f77628c5db26c9f145f4f2d4eb0a7faa78433fb8f01bab414c77c8a428438f7`。原始方案以原始文件字节保存。 [审查后实施方案](design/2026-11-13-receiver-evidence-v2.md)

- `native_bridge.py` 复用现有 `Vision.scan`，保留单次原生前向、CLIP 及 native16。补充只读 decoder hook 和 local9 解析，Swin 的 stage3 对应名义 stride 16。
- `targets.py` 依据 Objects365 清单中的 `known`、常规 GT 与原 crowd 规则核验。语义标签、供体关系、集合收益独立。六档使用原贪心一对一匹配和固定框分数，新版原槽稳定顺序进入匹配。
- `model.py` 实现冻结 Qwen、14 token 接收端、每条独立的 12 token 后缀、同模板 NULL、仅接收端视觉 value、有符号修正和 147 维收益读出。
- `train.py` 实现 A 自身、B 关系消息、C full/off 成对收益三阶段。B 使用冻结 A 的前缀缓存，真实和 NULL 后缀在每步重新前向并参与反传。C 固定 A/B 后生成成对输入。
- `predict.py` 和 `evaluate.py` 提供固定槽执行、一次策略锁定、预测封存及统一评估。政策前缀仅由 871 张 policy 图决定。基线 B 为项目历史 `graphllm_local_message_unique_v2` 的 JS-on 臂。仅迁移统一核验口径，沿用原锁定运行点。
- 旧阶段未通过资格检查的记录仍保留。按新规范，本轮合法早停和是否学到有效信号分别报告，JS 只作诊断。未添加风险硬门槛。

工程 smoke 在真实 GPU 上通过。解析坐标检查、真假模板对齐、正反向梯度、冻结、原槽执行和合成 COCO 评估均核对。旧 native16 和风险输入复用已有完全一致校验，并在三张历史放行图上复现原生输出与实际动作。初次 BF16 检查发现不同序列长度下前缀数值不一致，统一了掩码后的注意力长度。新实现中自身读取位置和有效 token 数保持为 14，12 个未来槽对 BASE 完全不可见。

阶段划分为 6,038 张训练图、807 张监控图、871 张策略图。新留出 2,048 图来自服务器已有 Objects365 归档，与项目既有图按源 ID、文件名、SHA-256 排重。留出独立性针对本项目的训练、选择与验证，不判断基础模型预训练图像身份。历史 2,048 图只用于已知对照的工程复现。

此前旧门控差额两条分别为仅丢原有匹配及已核验负例。冻结 v1 少列一条已核验负例。两项均已由历史缓存核对。
